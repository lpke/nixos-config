T3 Tailscale gateway
===================

Your phone uses Tailscale to reach this PC. The PC forwards the Mac's single
address over the home network. The Mac receives normal LAN HTTP traffic.
SSH stays first in desktop T3; this HTTP route is an independent backup.

Commands on the PC
  t3-tailscale start    Restore the T3 route and show the tray.
  t3-tailscale stop     Pause the T3 route, keeping the tray available.
  t3-tailscale status   Check route approval, forwarding and Mac identity.
  t3-tailscale quit     Pause the T3 route and close the tray.
  t3-tailscale help     Open these instructions.
  t3-tailscale logs     Show recent tray and Tailscale daemon logs.

The tray starts at desktop login and is always visible while running.
Its dotted ring distinguishes it from the solid-ring SSH icon. Green means
this PC is ready to forward T3 and the expected Mac environment responds.
Red means paused, disconnected, unapproved, misconfigured or unreachable.
Right-click for Start, Pause, Show logs, Help and Quit.

Pause and Quit withdraw only @ROUTE@. Other advertised routes and the main
Tailscale connection are preserved. Start restores this route; it does not
change T3 route order, log you in, reset settings or open a new SSH session.
Pause persists across app windows and reboots until Start. The tray returns
at the next desktop login even when paused. The boot-starting Tailscale daemon
remembers the last route preference and runs independently of the PC's T3 app.

Normal use
  Keep the PC and Mac on and awake. Leave T3 Network access enabled on the Mac.
  On your phone, connect Tailscale using the same personal account as the PC.
  In the native T3 phone app, choose your saved Mac environment.
  Address: @URL@
  The PC's T3 app may be closed. The Mac needs neither Tailscale nor an SSH
  listener for this HTTP connection. T3 still authenticates each paired client.

Pair a new phone or renew its permission
  1. On the Mac, open T3 Code Beta > Settings > Sharing & access.
  2. Select the Mac's local environment and create a fresh link with control
     access. Expand Share and use Copy code only, or scan the QR code.
  3. On the phone, choose Add environment and use @URL@ with that code.
     Create a separate code for each client; a used code cannot be reused.
  4. Verify the saved Mac environment opens an existing thread.
  Test with phone Wi-Fi off and mobile data on to verify the VPN path.

If red
  Run t3-tailscale status and t3-tailscale logs.
  Check that the Mac is awake and its T3 Network access is enabled.
  If approval is missing, open https://login.tailscale.com/admin/machines,
  select this PC and approve only @ROUTE@ in Subnets, then save.
  If Tailscale is signed out, run tailscale up and complete its browser login.
  The NixOS module owns forwarding, the forwarding filter and local operator
  permission. Reapply it if these are missing. Source NAT is a shared daemon
  preference; see the private runbook before changing it.

Configuration and policy
  ~/.config/tailscale-config/t3-gateway.json owns this helper's private target.
  Its README and docs/t3-mac-access.md own policy and recovery instructions.
  Policy changes are reviewed and saved in the Tailscale dashboard; pulling
  Git does not publish them. Credentials remain in Tailscale and T3 state.

Green checks this gateway and Mac identity, not the phone's internet connection
or pairing expiry. It cannot prove remote phone access without a phone test.
